# Novelty 與定位

先讀 `../paper-review-shared/conventions.md`，執行其中的「開始前」。問題編號用 P6-x（novelty）與 P8-x（整體判斷與定位）。

## 輸入
本 skill 的判斷建立在三份上游報告上：

| 上游報告 | 用到的內容 |
|---|---|
| `paper-survey-and-naive-ideas_*.md` | 領域脈絡、分組表、最接近的 2–3 篇工作、遺漏工作 |
| `paper-method-check_*.md` | 核心機制、深度判斷、設計決策表 |
| `paper-experiment-check_*.md` | 已證明與未證明的 claim 清單 |

## 缺少上游產出時
- 先執行缺少的 skill，再繼續。執行順序：survey → method → experiment。
- 無法執行（例如沒有 Skill tool）時，自行做該 skill 的核心檢查：survey 只找最接近的 3 篇工作，method 只寫核心機制，experiment 只核對主表是否支持主 claim。在「範圍與限制」標出哪些判斷沒有完整上游支撐。

## 檢查

### 1. 與最接近工作的差異
- 從 survey 報告取出最接近的 2–3 篇工作。
- 表格：維度（問題 setting、核心機制、理論、實驗範圍、結果）× 工作。每格寫具體差異與依據位置。
- 用一句話寫出本論文與最接近工作的關鍵差異（delta）。寫不出來時，列為 Fatal 或 Major。

### 2. 每項貢獻的新穎程度
- 列出論文宣稱的貢獻。
- 每項貢獻判斷：
  - 類型：新概念、既有方法的新組合、既有方法搬到新領域、新分析、新 benchmark。
  - 是否已被證明：依 experiment 報告。未被證明的貢獻不計入 novelty。
  - 是否已有前人做過：依 survey 報告與遺漏工作。找到撞題的工作時，列為 Fatal 並附引用。
  - 只是組合時，組合本身是否帶來非顯而易見的結果？依 method 報告的深度判斷。

### 3. 有沒有明顯 novelty
給出一個判斷，並說明依據：
- 明顯：至少一項已證明的貢獻是新概念，或帶來非顯而易見結果的組合。
- 有，但需要表述：novelty 存在，但論文的寫法讓 reviewer 看不出來。
- 不明顯：所有已證明的貢獻都是可預期的組合或搬移。
- 每項貢獻寫出建議表述：怎麼寫才能讓 reviewer 認可。表述不得超出實驗證明的範圍。

### 4. 定位
- 研究脈絡：論文屬於哪條研究線？延續或挑戰了哪些工作？
- 貢獻類型：新問題、新方法、新理論、新分析、新 benchmark，或實證研究。
- 目標讀者：哪個社群會引用這篇論文？

### 5. 定位評估
逐項判斷，並說明理由：
- 定位是否有證據支撐？claim 的範圍是否與實驗範圍相符？
- 定位是否太廣（無法證明）或太窄（貢獻顯得小）？
- 研究線是否過度擁擠，使貢獻難以凸顯？
- 定位是否符合目標會議的讀者與評分標準？
- 定位不佳時，提出 1–2 個更好的定位，並寫出每個定位需要哪些證據。

### 6. 整體判斷
- 綜合上游報告與本 skill 的結果，給出傾向：Accept、Borderline 或 Reject。
- 列出最強的 3 個優點與最嚴重的 3 個問題，附問題編號與理由。

## 輸出
- 報告 `paper-novelty-positioning_<zh 或 en>.md`，依共用規範的「每份報告的固定結構」撰寫：
  1. 結論：novelty 判斷、定位好壞、整體傾向。
  2. 差異表與一句話 delta。
  3. 貢獻表（宣稱、類型、是否已證明、前人工作、實際新穎程度、建議表述）。
  4. Novelty 判斷。
  5. 定位與定位評估；更好的定位（若有）。
  6. 整體判斷：傾向、3 個優點、3 個問題。
  7. 問題表（P6-x、P8-x）。
  8. 範圍與限制。
- 把 P6-x、P8-x 寫入 `issues.json`。
