# Reviewer personas

先讀 `../paper-review-shared/conventions.md`，執行其中的「開始前」。問題編號用 P10-x。
工作資料夾有其他報告時，先讀它們，避免重複提問；重複的問題標出原編號。

## 身分

| 身分 | 閱讀方式 | 提問方向 |
|---|---|---|
| 領域專家 | 逐節細讀，對照熟悉的方法 | 與 SOTA 的差距、遺漏的比較 |
| 領域新手 | 從頭讀，卡住就停 | 未定義的術語、跳過的推導 |
| 資深研究者 | 看研究脈絡 | 問題是否值得做、貢獻是否持久 |
| 嚴苛批評者 | 專找漏洞 | 能推翻主 claim 的反例 |
| 統計學家 | 看實驗設定與數字 | 顯著性、seed、variance、多重比較 |
| 方法學家 | 看實驗設計 | baseline 公平性、資料洩漏、調參預算 |
| 只讀標題、摘要和 Figure 1 的讀者 | 只看前兩頁 | 看完能否說出貢獻 |
| 只花 30 秒的 AC | 看摘要和主表 | 能否找到 reject 的理由 |

## 流程
1. 依序扮演每個身分。只用該身分的閱讀方式讀論文。例如 AC 只讀摘要與主表，不讀方法章節。
2. 每個身分至少提 3 題。問題要具體到論文的內容，例如引用 Table 2 的數字或 Eq. 5 的符號。
3. 每題記錄：
   - 問題。
   - 在論文中搜尋的位置。
   - 是否找到答案：找到（寫位置）、部分找到、沒找到。
   - 嚴重度：沒找到答案、而且足以動搖主 claim 時列為 Fatal。
4. 優先列出足以推翻論文的問題。
5. 自己的論文：每題再寫兩欄。
   - Rebuttal 草稿：2–3 句，只用論文中已有或可以補上的證據。
   - 論文該補的位置：要在哪一節加一句話、一張表或一個實驗，讓 reviewer 不必問。

## 輸出
- 報告 `paper-reviewer-personas_<zh 或 en>.md`，依共用規範的「每份報告的固定結構」撰寫：
  1. 結論：最可能導致 reject 的 3 個問題。
  2. 每個身分一張表（問題、搜尋位置、是否找到、嚴重度；自己的論文加 rebuttal 草稿與該補的位置）。
  3. 問題表（P10-x）：只列沒找到或部分找到答案的問題。
  4. 範圍與限制。
- 把 P10-x 寫入 `issues.json`。
